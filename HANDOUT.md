## 0. Working rules (the user's standing instructions)

1. **Language and reporting.** Talk to the user in Chinese, concisely. Continue autonomously within the requested scope; ask only when a decision is genuinely theirs. Never claim a game test that did not happen: say what was checked headlessly, what was seen in game, and what remains untested.
2. **Git: commit and push directly to `master`.** No other branches, no pull requests, no tags and no releases unless the user asks (tags trigger the release workflow). If the environment checks out or suggests another branch, still build on top of `origin/master` and push there.
   ```sh
   git fetch origin master          # always first; rebase or merge if master moved
   git -c user.name=HackerRouter -c user.email=1566032@qq.com commit -m "Describe the change"
   git push origin HEAD:master
   ```
   Commit each coherent, built and tested portion; do not push a broken build.
3. **Nothing AI-related in the repository or its history.** Commit messages contain only a description of the change: no `Co-Authored-By` or other trailers, no session or tool links, no "generated with" lines, no signatures. Do not mention assistants, models, prompts or chat sessions in commit messages, code, comments, documentation, file names or branch names, and never refer to these rules in a commit message. `README.md` is written by the maintainer, including its notes about how parts of the project were produced (around lines 56-60 and 290-293): keep those as they are and only update feature descriptions when a change needs it.
4. **Code style.** Few comments, short and only where needed. Preserve license headers, SPDX lines and attributions; new files carry a one-line header like the existing ones (`// <what>, by HackerRouter, 2026.`; adapted LGPL files keep their notice). Match the surrounding code.
5. **Translations.** Reuse Litematica/MaLiLib translation keys whenever the meaning matches (section 8). Plus-only keys go into `src/main/resources/assets/schematica/lang/en_US.lang` and `zh_CN.lang`.
6. **References and licenses.** AGPL sources (litematica-printer) and all-rights-reserved ones (Buildprint) are behaviour references only: never copy their code. Closed-source mod jars may be decompiled only to learn NBT formats, field names and rendering inputs. MIT/CC0/public-domain material may be adapted with attribution in `THIRD_PARTY_NOTICES.md`.
7. **Documentation.** For every completed portion add an entry to this file (status word, date, what and where; section 6 lists them) and in-game steps to `TESTING.md`.
8. **User files.** Saves or schematics the user uploads are evidence: work on copies, never modify or publish the originals.

## 0A. Resume protocol and status vocabulary

1. `git fetch origin master`, `git status`, `git log --oneline -20`; read this file, `TESTING.md` and `compatibility/README.md`. `compatibility/ui-port.md` is a chronological journal (later phases supersede earlier "pending" lines). README is the user-facing feature list.
2. Build and test before changing anything (section 2), so later failures can be told apart from environment problems.
3. Work on the user's current request; otherwise continue with section 11.

- `IMPLEMENTED_HEADLESS`: implemented, automated checks pass; not (fully) seen in a real game.
- `VISUAL_CHECKED_HEADLESS`: additionally observed in a game started in the cloud container (section 2A); a real GPU, the user's own pack and multiplayer may still differ.
- `DONE`: finished non-code work (audits, documentation).
- `WIP_UNWIRED`: partial source without completed behaviour.
- `OPEN`: missing behaviour or a reported defect without evidence of resolution.
- `REGRESSION_REQUIRED`: a fix exists; the scenario still needs a real game/pack test.
- `PARITY_AUDIT`: equivalence with upstream not established; investigate before asserting a defect.
- `UPSTREAM_PLACEHOLDER`: the chosen upstream reference does not implement the operation either.
- `LIMITATION`: version/protocol/context constraint; explain accurately instead of claiming a fix.

### Driving the game

`tools/headless/x.sh` wraps xdotool and ImageMagick (`DISPLAY_NUM=:99` dev client, `:98` GTNH; `SHOT_DIR` for screenshots):

- `x.sh shot NAME`, then look at the PNG; crop and enlarge details with PIL. Coordinates below are for 1280x720 with the default GUI scale.
- Clicks need a pause between press and release (`x.sh clk X Y`); a fast `xdotool click` is often lost in lists.
- Camera: `x.sh look DX DY` moves the mouse relatively in small steps (absolute moves do not turn the view); 1200 px is about 180 degrees.
- In-game keys must be held briefly: `x.sh tap m` opens the Plus menu. Chat: `x.sh chat "/tp @p X Y Z"` (1.7.10 `/tp` takes no yaw/pitch). `/save-all` typed this way came back as an unknown command; rely on the autosave (about every 45 s) and the region file times.
- Flying in Creative: two quick space taps, then hold space. `/gamemode 1` if the save was survival.
- Plus specifics: `executeOperation` is unbound by default. Bind it while the game is closed in `rc2/config/schematica_plus_hotkeys.json` (LWJGL key codes; F7 = 65 was used, but GTNH also toggles its mob spawning overlay on F7). Execute needs the tool item in hand (stick, `executeRequireTool`) and a selected placement (clicking an already selected row in Schematic Placements deselects it). The paste tool mode is chosen with the Tool Mode button at the bottom of the main menu. Text fields: click, ctrl+a, BackSpace a few times, type.
- WAILA (GTNH) tells whether a multiblock formed ("Running Fine" or "INCOMPLETE STRUCTURE") and its facing; aim at the controller with small `look` steps.
- Plus's `/schematicaSave x1 y1 z1 x2 y2 z2 name` saves a world box without the selection UI (the file appears in `schematics/`, `.schemplus` when extended ids or metadata are needed).

### Checking pastes without the UI

`tools/headless/regions.py` reads the saved region files (vanilla and EndlessIDs sections) and a `.schematic`/`.schemplus`:

```sh
R=rc2/saves/<world>/<DIM>/region
python3 tools/headless/regions.py tiles  $R --box x0,y0,z0,x1,y1,z1                 # what is where (tile entities)
python3 tools/headless/regions.py verify schematics/a.schemplus $R --box ...         # finds the rotation/mirror, checks GT/AE2 orientation data
python3 tools/headless/regions.py blocks schematics/a.schemplus rc2/saves/<world>/level.dat $R --matrix '<from verify>' --offset '<from verify>'
python3 tools/headless/regions.py around rc2/saves/<world>/level.dat $R --box ...     # structure parts just outside a saved box
```

A multiblock whose structure reaches past the saved box cannot form after pasting, and GT pipes on the box edge drop the connection to the missing outside neighbour; `around` and `verify` show both. Saves made before the paste may still be in memory: check the region file times.

Persistence invariants:

- Loaded source and placement are distinct. Multiple placements can share one immutable source snapshot; placement transforms must not mutate it. Unload source vs remove placement has different effects.
- Per-world/server/dimension session identity matters. `LoadedSchematics.json`, `AreaSelection.json`, render-layer/session storage and older coordinates migration must not leak to another world. Old unreadable/future schemas must not be overwritten silently. Preserve unknown JSON fields where the existing code does so.
- AreaSelection v5 stores Normal and Simple independently. Older v2-v4 and original coordinate-only data migrate. Subregion-placement JSON v2 preserves signed anchors; v1 migration maintains world geometry.
- Capture/edit size bounds: 16,777,216 blocks, 32,767 per axis, 1,048,576 X/Y rows; NBT 128 MiB allocation budget and depth 64; world Y=0..255. World MOVE has the stricter 1,048,576 enclosing-cell bound. Validate before allocating/writing.
- Canonical tile/entity NBT and client-only visual payload are separate. Partial client packets must not erase full inventories/machine state on later saves or paste. Preview machinery must not tick real machine logic, mutate static registries/shared storage, send network packets, play machine sounds or alter the actual world.
